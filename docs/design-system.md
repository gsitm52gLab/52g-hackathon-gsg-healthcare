# GS HALE 디자인 시스템

상태: `baseline`  
대상: 데스크톱 우선 반응형 B2B 운영 플랫폼  
접근성 기준: WCAG 2.2 AA

## 1. 목표

GS HALE의 디자인 시스템은 예쁜 화면을 만드는 장식 규칙이 아니라, 복잡한 해외 진출 업무에서 사용자가 다음 네 가지를 놓치지 않게 하는 운영 계약입니다.

1. 지금 해야 할 일
2. 누가 책임지는지
3. 어떤 버전과 사용 범위인지
4. 무엇이 사실·사람 결정·AI 제안인지

## 2. 벤치마크

특정 시스템의 외형이나 코드를 그대로 복사하지 않습니다. 다음 원칙만 채택합니다.

| 시스템 | 가져올 원칙 | GS HALE 적용 |
| --- | --- | --- |
| [IBM Carbon](https://carbondesignsystem.com/) | 중립 표면, 데이터 밀도, 접근성, 명확한 주 행동 | 운영 홈·표·검수 화면을 차분하고 정보 중심으로 구성 |
| [Atlassian Design System](https://atlassian.design/foundations/design-tokens) | 원시값이 아닌 의미 기반 토큰 | `blue-600` 대신 `color.action.primary` 사용 |
| [Shopify Polaris](https://shopify.dev/docs/api/polaris) | 관리자 업무와 객체 중심의 일관된 행동 패턴 | 요청·파일·검수 결과마다 동일한 헤더와 작업 구조 사용 |
| [WCAG 2.2](https://www.w3.org/TR/WCAG22/) | 대비, 키보드, 포커스, 오류 예방, 색상 외 단서 | AA를 최소 완료 조건으로 적용 |

## 3. 디자인 원칙

### 3.1 Action first

페이지 상단에는 추상적인 상태 요약보다 `해야 할 일`, 책임자, 기한을 먼저 둡니다. 하나의 화면에는 하나의 대표 행동만 강조합니다.

### 3.2 Evidence attached

검수·승인·완료 문구 옆에는 주체, 시각, 대상 버전, 사용 범위와 근거 링크를 연결합니다. 연결되지 않은 상태 배지는 만들지 않습니다.

### 3.3 Calm density

업무 정보는 충분히 보여주되 카드와 색상을 남용하지 않습니다. 표·리스트·구획선으로 구조를 만들고 여백은 관계를 설명하는 데 사용합니다.

### 3.4 Human accountable

AI는 후보를 만들 수 있지만 판정 주체처럼 보이면 안 됩니다. 사람의 검토 상태와 AI 사전검토 상태는 별도 필드와 컴포넌트로 표시합니다.

### 3.5 Progressive disclosure

기본 화면에는 다음 행동과 필수 맥락을 보여주고, 원문·감사 로그·상세 근거는 펼쳐 봅니다. 중요한 제한이나 오류를 접힌 영역에만 숨기지 않습니다.

## 4. 토큰 모델

토큰은 `foundation → semantic → component` 3단계로 관리합니다.

```text
foundation.color.gs.blue = #3366CC
        ↓
semantic.color.action.primary = #2854AD
        ↓
component.button.primary.background = {color.action.primary}
```

규칙:

- 제품 코드에서는 가능한 한 semantic token을 사용합니다.
- component token은 실제로 둘 이상의 화면에서 재사용될 때만 추가합니다.
- 임의의 hex, 픽셀 간격, 그림자 값을 컴포넌트 안에 직접 추가하지 않습니다.
- 이름은 보이는 색이 아니라 역할을 설명해야 합니다.

### 5.3 색상 사용 규칙

- 일반 본문 텍스트 대비는 최소 `4.5:1`, 큰 텍스트와 UI 경계는 최소 `3:1`을 충족합니다.
- `color.border.default`는 장식적 구획에만 사용합니다. 입력 필드처럼 경계가 컴포넌트를 식별하는 경우 흰 배경 대비 `3:1` 이상인 `color.border.strong` 또는 포커스 토큰을 사용합니다.
- 색상만으로 상태를 구분하지 않습니다. 라벨과 아이콘 또는 형태를 함께 씁니다.
- 초록은 **사람 또는 규칙으로 완료 조건이 확인된 경우**에만 사용합니다.
- AI 결과에는 성공 초록을 사용하지 않습니다.
- Orange는 브랜드 에너지 강조나 경고 중 하나로 한 화면에서 역할을 섞지 않습니다. 제품 UI에서는 경고 시맨틱 값을 우선합니다.
- 위험도와 신뢰도는 별도 필드입니다. 높은 위험·낮은 신뢰를 하나의 중간 색상으로 합치지 않습니다.

## 6. 타이포그래피

### 글꼴

```css
font-family: Pretendard, "Noto Sans KR", "Noto Sans JP", Inter,
  -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
```

- 한국어와 라틴 문자는 Pretendard를 우선합니다.
- 일본어 원문은 Noto Sans JP fallback을 보장합니다.
- 숫자·버전·시간은 tabular number를 지원하면 적용합니다.
- 장문 본문에 600 이상의 굵기를 사용하지 않습니다.

### 타입 스케일

| 토큰 | 크기/행간 | 굵기 | 용도 |
| --- | --- | --- | --- |
| `type.display` | `32/40` | 700 | 랜딩·데모 핵심 메시지 |
| `type.heading-1` | `28/36` | 700 | 페이지 제목 |
| `type.heading-2` | `22/30` | 700 | 주요 섹션 |
| `type.heading-3` | `18/26` | 600 | 패널·객체 제목 |
| `type.body` | `15/24` | 400 | 기본 본문·테이블 |
| `type.body-small` | `14/20` | 400 | 보조 정보 |

| `type.caption` | `12/18` | 400 | 제한된 메타데이터 |

모바일에서도 기본 본문은 `14px` 아래로 낮추지 않습니다.

## 7. 간격·크기·형태

### 간격

4px 기반 스케일을 사용합니다.

```text
space.0  = 0
space.1  = 4px
space.2  = 8px
space.3  = 12px
space.4  = 16px
space.5  = 20px
space.6  = 24px
space.8  = 32px
space.10 = 40px
space.12 = 48px
space.16 = 64px
```

### 크기

- 기본 컨트롤 높이: `40px`
- 조밀한 테이블 컨트롤: `32px`
- 터치 타깃 최소: `44 × 44px`; 조밀 모드에서도 클릭 가능한 행 전체로 보완합니다.
- 본문 최대 읽기 폭: `720px`
- 앱 콘텐츠 최대 폭: `1440px`

### 형태와 깊이

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `radius.control` | `6px` | 입력·버튼 |
| `radius.panel` | `10px` | 패널·카드 |
| `radius.badge` | `999px` | 짧은 상태 배지 |
| `shadow.overlay` | `0 12px 32px rgba(24,32,36,.16)` | 모달·팝오버만 |

기본 카드에는 그림자를 쓰지 않고 배경·경계·간격으로 계층을 만듭니다.

## 8. 레이아웃

### 데스크톱

```text
┌──────────────────────────────────────────────────────────┐
│ Global header                                            │
├────────────┬─────────────────────────────┬───────────────┤
│ Navigation │ Main work area              │ Context panel │
│ 240px      │ fluid                       │ 320px optional│
└────────────┴─────────────────────────────┴───────────────┘
```

- 메인 영역은 12열 그리드, `24px` gutter를 기본으로 합니다.
- 오른쪽 Context panel은 근거·버전·감사 이력에 사용하며, 핵심 행동을 이 영역에만 두지 않습니다.
- 데이터 표는 화면 폭을 우선 사용하고, 장문 설명은 읽기 폭을 제한합니다.

### 반응형

| 구간 | 동작 |
| --- | --- |
| `≥ 1280px` | 3영역 앱 셸 허용 |
| `768–1279px` | 내비게이션 축소, Context panel drawer 전환 |
| `< 768px` | 단일 열, 표는 핵심 열 고정 후 상세 drill-in |

모바일에서 중요한 상태·기한·대표 행동을 가로 스크롤 뒤로 보내지 않습니다.

## 9. 핵심 컴포넌트

### App shell

- GS HALE 제품명, 현재 조직/브랜드, 전역 검색, 알림, 사용자 메뉴를 포함합니다.
- 공식 GS 로고를 사용할 때는 승인된 asset과 clear space를 유지합니다.

### Page header

순서: Breadcrumb → 제목 → 대상/버전 메타 → 대표 행동 → 보조 행동.

### Work queue

각 행에 다음 항목을 우선 표시합니다.

1. 해야 할 일
2. 대상 브랜드·제품
3. 책임자
4. 기한과 시간대
5. 대기 상대 또는 차단 사유
6. 정확한 제출/검수 버전

`진행 중` 같은 단일 상태만으로 행을 설명하지 않습니다.

### Status badge

- 구조: 아이콘 + 짧은 라벨
- 허용 예: `답변 대기`, `외부 확인 중`, `보완 필요`, `사람 검토 완료`
- 금지 예: 맥락 없는 `완료`, AI 결과의 `통과`
- 배지가 3개를 넘으면 가장 중요한 상태 2개와 `+N` 상세를 사용합니다.

### Version chip

파일명만 표시하지 않고 `v3 · 일본어 패키지 · 2026-09-21 16:20 KST`처럼 버전과 맥락을 함께 보여줍니다.

### Review finding

순서: 위험도 → 문제 span → 제안 → 법적 근거 → 보조 가이드 → 신뢰도 → 사람 판정.

- `위험도`와 `신뢰도`를 같은 배지에 넣지 않습니다.
- 정확한 locator가 없으면 `정확한 근거 위치 미확인`을 카드 상단에서 보이게 합니다.
- AI finding에는 항상 `AI 사전검토 · 사람 확인 필요`를 표시합니다.

### Timeline / audit log

- 누가, 언제, 무엇을, 어떤 버전에 수행했는지 문장으로 읽혀야 합니다.
- 최신 기록을 기본으로 보여주되 이전 버전을 삭제하거나 덮어쓰지 않습니다.
- 시스템 이벤트와 사용자 행동을 아이콘뿐 아니라 텍스트로 구분합니다.

### Form

- 라벨은 placeholder로 대체하지 않습니다.
- 필수 여부, 입력 형식, 오류 해결 방법을 입력 전에 알 수 있게 합니다.
- 저장 실패 시 사용자가 입력한 값을 유지합니다.
- 법적·공개·최종 전달처럼 위험한 행동은 대상과 결과를 확인하는 단계를 둡니다.

### Empty / loading / error

- Empty: 왜 비어 있는지와 가능한 다음 행동을 제공합니다.
- Loading: 400ms 이하는 표시하지 않고, 그 이상은 레이아웃을 보존하는 skeleton을 사용합니다.
- Error: 발생한 일, 보존된 내용, 재시도 방법, 지원 경로를 제공합니다.
- 부분 실패를 전체 성공처럼 표시하지 않습니다.

## 10. 행동 위계

| 단계 | 표현 | 한 화면의 권장 수 |
| --- | --- | --- |
| Primary | 채워진 GS Blue 버튼 | 1개 |
| Secondary | 경계 버튼 | 1–2개 |
| Tertiary | 텍스트/ghost 버튼 | 필요 시 |
| Destructive | Danger 버튼, 확인 단계 | 위험 행동에만 |

- 버튼 라벨은 `확인`, `진행`보다 `수정본 제출`, `검수 요청 기록`처럼 결과를 설명합니다.
- 실제 외부 발송이 아닌 기록 기능은 `발송`이라고 쓰지 않습니다.
- 비활성 버튼만 두지 말고 조건과 해결 방법을 가까이에 표시합니다.

## 11. 상태 모델

상태색은 객체의 실제 상태를 대신하지 않습니다. 다음 기본 매핑을 사용합니다.

| 의미 | 시맨틱 | 예시 |
| --- | --- | --- |
| 미시작·열림 | Neutral | 미확인, 미제출 |
| 진행·정보 | Info | 검토 중, 답변 작성 중 |
| 대기·주의 | Warning | 외부 답변 대기, 기한 임박 |
| 사람 확인 완료 | Success | 제출 확인됨, 전문가 검토 완료 |
| 오류·차단·고위험 | Danger | 필수 정보 누락, 사용 차단 |
| AI 생성 결과 | AI/Info | 사전검토 finding |

완료는 객체 유형별 완료 조건이 충족된 경우에만 사용합니다. `파일 업로드됨`, `검수 요청됨`, `검수 완료`, `최종 사용본 전달됨`은 서로 다른 상태입니다.

## 12. 콘텐츠와 국제화

- 기본 UI는 한국어로 작성하되 일본어 원문을 원형 그대로 병기할 수 있어야 합니다.
- 번역문에는 `비공식 번역`, 검수 상태와 번역 버전을 표시합니다.
- 날짜는 `2026-09-22 12:00 KST`처럼 절대 시각과 시간대를 사용합니다.
- 상대 시간은 보조로만 사용합니다: `3시간 전 · 2026-09-21 14:04 KST`.
- 긴 영문·일본어 파일명과 URL은 레이아웃을 깨지 않게 줄바꿈하고 전체값 접근 수단을 제공합니다.
- 위험·오류·완료 문구는 번역만으로 확정하지 않고 도메인 용어집을 따릅니다.

## 13. 모션

- 기본 전환: `150–200ms`, ease-out
- 작업 흐름 변화: 최대 `300ms`
- `prefers-reduced-motion`을 존중합니다.
- 상태 변경을 색 변화나 애니메이션만으로 전달하지 않습니다.
- 파도·pulse 모션은 랜딩의 제한적 브랜드 표현에만 사용하고 운영 화면에서는 사용하지 않습니다.

## 14. 접근성 완료 조건

- 키보드만으로 모든 행동을 수행할 수 있습니다.
- 포커스 순서는 시각 순서와 일치하고, 포커스 링을 제거하지 않습니다.
- 일반 텍스트 `4.5:1`, 큰 텍스트와 UI 경계 `3:1` 이상입니다.
- 색상 외 텍스트·아이콘·형태로 상태를 식별할 수 있습니다.
- 확대 `200%`와 폭 `320 CSS px`에서 핵심 기능이 손실되지 않습니다.
- 오류는 필드와 프로그램적으로 연결되고 해결 방법을 설명합니다.
- toast만으로 중요한 결과를 전달하지 않으며 적절한 live region을 제공합니다.
- 표에는 헤더 관계, 정렬 상태와 행 단위 행동의 접근 가능한 이름이 있습니다.

## 15. AI/Goal 에이전트 판단 계약

에이전트가 시안에 없는 상황을 만났을 때 아래 순서로 결정합니다.

1. **안전과 업무 진실성:** 법률 판단, 승인, 완료를 추정하지 않습니다.
2. **정확한 연결:** 대상 브랜드, 제품, 버전, 사용 범위와 근거를 보존합니다.
3. **다음 행동:** 책임자, 기한, 차단 사유를 우선 노출합니다.
4. **접근성:** 키보드, 대비, 텍스트 대체, 오류 예방을 지킵니다.
5. **기존 패턴:** 새 패턴보다 기존 토큰과 컴포넌트를 재사용합니다.
6. **브랜드 표현:** 위 조건을 만족한 뒤 GS HALE의 시각 언어를 적용합니다.

### 기본 판단표

| 의문 | 기본 결정 |
| --- | --- |
| 어떤 색을 써야 하는가? | 의미에 맞는 semantic token을 사용하고 새 hex를 만들지 않음 |
| 카드인가 표인가? | 반복 객체 비교는 표/리스트, 독립된 단일 객체는 패널 |
| 모달인가 페이지인가? | 짧고 되돌릴 수 있는 작업만 모달, 검토·비교·다단계 작업은 페이지 |
| 상태가 애매한가? | 가장 보수적인 비확정 상태와 이유를 표시 |
| AI 결과가 비어 있는가? | `문제없음`이 아니라 `탐지 결과 없음`과 실행 상태를 표시 |
| 근거 locator가 없는가? | 추측하지 않고 `정확한 근거 위치 미확인` 표시 |
| 기한이 없는가? | 임의 생성하지 않고 `기한 미정` 및 확인 책임자 표시 |
| 여러 Primary action이 필요한가? | 사용자의 다음 단계 하나만 Primary로 두고 나머지는 Secondary |
| 새로운 컴포넌트가 필요한가? | 두 화면 이상 재사용과 기존 패턴 불충분을 문서로 입증한 뒤 추가 |
| 브랜드와 접근성이 충돌하는가? | 접근 가능한 파생 토큰을 사용하고 공식 로고 자체는 변경하지 않음 |

### 에이전트 금지 사항

- AI finding을 초록색 `통과/승인`으로 표시
- 새 제출본에 이전 승인을 자동 승계
- 브랜드 간 데이터나 상태를 한 화면에서 노출
- 기한·검수기관·승인 범위를 추측
- 원본 일본어와 비공식 번역을 구분 없이 표시
- 장식 목적으로 GS CI 원색을 모든 컴포넌트에 분산 사용
- 화면마다 다른 상태명과 버튼 동사 생성

## 17. 확장 절차
